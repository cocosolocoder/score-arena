# ScoreArena

桌面规则游戏与赛事管理。

需要Go 1.22 或更新版本。

查看命令帮助：

```sh
go run . --help
```

启动本地服务：

```sh
go run . serve --host 127.0.0.1 --port 8080 --data-dir data
```

打开 http://127.0.0.1:8080 查看首页。Ctrl+C 停止服务。`--data-dir` 指定本地业务数据目录，重启时继续使用同一目录，房间编号与配置保持不变。

首页可以创建公开房间：填写房间名称、选择游戏规则（五子棋 / 飞行棋）、人数上限与每步时间限制后提交；创建成功后同一页立即展示新房间，失败时保留已填内容并提示原因。房间列表展示编号、名称、规则、人数上限、时间限制（0 显示为“不限时”）、状态（waiting 显示为“未开始”）和创建时间；没有房间时显示空列表提示。

接口：

- `GET /health` 返回服务状态和产品名称。
- `GET /api/rooms` 返回房间列表，外层为 `{"rooms": [...]}`，首次启动时为空。
- `POST /api/rooms` 创建公开房间。请求体必须是单个 JSON 对象，字段为 `name`、`game`、`capacity`、`turnSeconds`，全部必填：
  - `name`：字符串，去掉首尾空白后为 1 至 40 个 Unicode 码点，内部空格保留。
  - `game`：`gomoku`（五子棋）或 `ludo`（飞行棋）。
  - `capacity`：整数。五子棋固定为 `2`；飞行棋为 `2` 至 `4`。
  - `turnSeconds`：整数秒，`0` 表示不限时，其余只允许 `10` 至 `600`。
  - 成功返回 `201` 和 room 对象：服务生成的非空且不重复 `id`、固定 `status: "waiting"`、固定 `visibility: "public"` 以及创建时刻 `createdAt`。
  - 请求体不是单个 JSON 对象、字段缺失、类型不符、规则未知、人数/时间含小数或超出范围时返回 `400` 及具体 `error`，不写入任何记录。
  - 数据文件无法读取、不是合法数组或保存失败时返回 `500`，已有数据不会丢失或被重置。
- 未知路径返回 404；已知地址不支持的方法：`/` 与 `/health` 返回 405 且 `Allow: GET`，`/api/rooms` 返回 405 且 `Allow: GET, POST`。

房间数据保存在 `--data-dir` 下的 `rooms.json`（顶层数组），已有的房间记录及其附带字段会原样保留。

## 回归测试

接口与本地保存的回归测试（Go，启动真实服务子进程）：

```sh
go test ./...
```

`main_restart_test.go` 以真实子进程覆盖“正常停止（SIGINT，等同 Ctrl+C）后使用同一 `--data-dir` 重新启动”的保留行为：停止前创建的五子棋（`turnSeconds: 0`）与飞行棋（有限时整数秒）房间重启后数量、排列次序、编号一致，名称（仅去首尾空白，内部空格与表情保留）、规则、人数、时间、状态、公开范围、创建时间保持原值，不补默认值、不串用配置；带备注/数组/嵌套对象的附带字段与缺少当前表单字段的历史记录原样保留，启动和只查询列表不改写本地文件，重启后新建房间只追加在旧记录之后且编号非空不重复；停止后数据被截断或顶层为 `null` 时，查询与合法创建均返回 500（error 指向房间数据读取/解析），原数据逐字节保留；真正的空数组重启后仍是成功的空列表，随后创建的第一条记录可正常查到。

`main_single_object_test.go` 围绕 `POST /api/rooms` 的入口约定“每次提交只能包含一个完整的 JSON 对象”做回归：请求体为空、只有空白、不是合法 JSON，或顶层为 `null`、字符串、数字、布尔值、数组（含仅装着唯一一个配置合法房间对象的数组）时一律返回 400，error 固定说明请求体必须是单个 JSON 对象、不返回房间编号，且不归为房间数据读取失败或字段级错误；对象未结束就中断的载荷不留半条记录；一个合法配置之后还跟着第二个对象、其他 JSON 值或任何非空白字符时整个请求被拒绝，不会先保存前面对象再报错（已保存房间的数量、次序、配置、附带字段与本地文件均不变）；与此相对，合法配置前后只有空格、制表符、CRLF 或换行时正常创建，名称内部的花括号、方括号与按 JSON 规则转义的引号作为名称内容保存，首尾空白仍按既有规则整理；被一系列错误请求拒绝后修正为单个合法对象，返回 201，列表仅在原记录之后追加这一条且与创建响应一致，被拒请求不占任何记录；该固定错误信息与缺少字段、类型不符、名称为空等既有字段校验错误保持可区分。

`main_parallel_create_test.go` 回归“多个用户在同一服务中同时提交创建房间”的保存结果：多个 goroutine 经闸门同时放行，向同一真实服务子进程发起 POST，每一份返回 201 的合法提交都成为独立房间——非空编号两两不重复且不与已有编号冲突，每份响应只携带自己提交的名称（只去首尾空白，内部空格与表情保留）、规则、人数、每步时间，状态与公开范围仍为 `waiting`、`public`，规则、人数和时间不串到另一份响应；同一批中五子棋与飞行棋、不限时（`0`）与有限时（`10`/`45`/`600` 等）混合提交，同名的两份合法提交也各自创建、不按名称合并。全部处理完成后，房间列表与本地保存内容都包含全部成功房间：最终记录数恰好等于旧记录加成功创建数，每个成功编号恰好对应一条追加在原记录之后的新记录且配置与创建响应一致（并行新房间之间不要求按提交或响应先后排序），不能只留下最后完成的提交；已有房间及其备注、数组或嵌套附带字段保持原值和原有相对次序，历史数据中的缺字段对象与 `null`、字符串、数字、布尔值、数组等非对象记录原样保留，不被补齐、清理或展开。同一批混入的五子棋四人无效提交仍返回 400 且明确说明人数与规则不符，不返回成功编号、不占保存记录，查询仍能看到完整旧记录和合法新记录；空历史上的并发创建同样全部落盘。该保障只针对业务数据能正常读取、保存时的同时创建行为，沿用现有错误提示与数据兼容约定。

首页创建公开房间的界面回归测试（Node.js + 系统 Chrome，真实浏览器加载真实服务页面，覆盖成功提示、表单复位、列表刷新、创建被拒、创建连接失败与列表刷新失败，名称的首尾空白整理、U+FEFF 保留、按码点计的长度边界与页面拦截行为，规则与人数联动，以及每步时间限制从填写、提交到新房间展示的行为）：

```sh
npm install
npm test
```

`npm test` 会同时运行七个浏览器回归文件：

- `ui.test.mjs`：创建成功/被拒、成功后列表竞态刷新、名称整理与长度边界。
- `ui-capacity-linkage.test.mjs`：游戏规则与人数上限的联动——未选规则禁用人数、五子棋自动固定 2 人、飞行棋 2/3/4、来回切换以当前选择为准（含 4→2→切回仍为 2）、切换时名称/时间保留、切回空规则后旧人数失效、缺规则/缺人数的页面拦截（不发请求、不增房间、内容保留），以及请求体、创建结果与房间列表三处规则/人数的端到端一致性（飞行棋 3 人与 4 人分别验证）。
- `ui-turn-seconds.test.mjs`：每步时间限制——0 显示“不限时”、10/600 两个端点与区间内整数的请求体/创建结果/房间列表记录三处秒数一致及页面展示（五子棋与飞行棋共用一套时间规则，人数按各自规则选择）；未填提示必填、负数/1-9/超 600/小数的页面拦截（不发请求、不增房间、列表不变、内容保留、按钮可用），以及看到时间错误后只改时间再提交的修正流程（修正值创建、被拒值不入记录、其余配置沿用、成功后表单复位与列表刷新、错误提示被成功结果替换）。
- `ui-mixed-records.test.mjs`：房间列表的混合记录展示——只有 JSON 对象成为房间行，`null`、字符串、数字、布尔值、数组全部跳过并给出准确条数与“原始数据仍保留在服务端”的说明；对象按返回数组中的相对次序成行，五子棋/飞行棋中文名、0 秒“不限时”、waiting“未开始”等现有展示保留；带额外字段与缺字段（含空对象）的对象仍成行且不计跳过，空数组与装着房间对象的数组都不展开，空字符串、数字 0、布尔值 false 不漏计；数组非空但全部跳过时说明没有可展示的房间与跳过总数（无表格、无“还没有房间记录”），只有真正的空数组才显示空列表提示且无跳过警告；某个展示字段被存成 JSON 对象或数组时（如名称为 `{"toString":"旧名称"}`），只把对应单元格替换为“字段格式异常”（异常人数/时间不附“人/秒”，异常创建时间不显示日期悬浮说明，内部内容不展开），同一房间其余字段与其他房间行照常显示，异常对象位于开头/中间/末尾都成行、不计跳过，即使所有行都含异常字段也保留表格、不显示空列表或全部跳过提示；查看列表与混排数据下创建房间后，接口原始记录与本地文件的数量、次序、类型和附带字段保持不变。
- `ui-create-connection-failure.test.mjs`：创建请求尚未送达服务就连接失败的回归——先正常加载已有房间，再填写合法的飞行棋配置（4 人、60 秒，名称含首尾空格、内部空格与表情）；提交等待期间创建按钮不可用，连接失败后表单区域显示“无法连接服务，请确认服务仍在运行后重试。”（不显示成输入错误或列表读取失败），按钮恢复可用，名称保持输入原貌，规则、人数、时间全部保留且人数选择仍可用；房间列表保留提交前的内容与次序，不出现新房间、成功提示或虚假编号，服务端记录不增加且已有记录及附带字段保持原值；连接恢复后不刷新页面、不重新填写直接再次提交即可创建，新房间沿用保留的飞行棋/4 人/60 秒配置，名称仅去首尾空白（内部空格与表情保留），成功提示的非空编号与服务端返回一致，列表在已有记录之后展示新房间且原有记录不变，连接失败提示被成功结果替换，表单恢复初始填写状态，创建按钮仍可使用。失败条件限定为请求未送达服务（以服务端记录数不变佐证），不把响应途中断开时房间是否已保存作同样判断；既有区分继续保留——服务已确认创建成功而后续列表刷新连接失败时，仍保留成功提示及编号，不按创建连接失败处理。
- `ui-name-plain-text.test.mjs`：房间名称的纯文本展示——从首页填写含尖括号、引号、与号及链接/标签样式文字的名称并创建公开房间，到列表更新的完整过程：名称符合现有长度与非空要求即正常创建（页面不拦截、不删标点、不截断），创建响应、房间列表接口与本地保存的名称都与仅去首尾空白后的原文逐字一致（不保存成 &lt; 之类的转义写法），成功提示仍显示本次编号；页面上的名称逐字可读，不变成加粗文字、可点击链接、图片或额外按钮，也不改变本行其他列与相邻房间；带事件属性与脚本样式的名称展示后不引发弹窗、页面跳转或额外操作；类似字符实体的文字（&lt;、&amp;）按原有写法显示、不再解释成另一种字符；已有记录中的标签样式与实体样式名称首次打开按原文展示，新建房间导致列表更新后仍保持原文、相对次序与其他配置不变，查看与新建都不改写已有记录，新房间只追加一条正常记录。
- `ui-created-time.test.mjs`：房间列表创建时间列的显示约定——用逐页固定的浏览器时区（东八区、固定西五区、UTC、国际日期变更线等）回归本地时间换算：能识别的创建时间显示为“YYYY-MM-DD HH:mm:ss”，月、日、时、分、秒不足两位补零；带时区偏移的原文按实际时刻换算，跨日、跨月、跨年的日期对应当地时间（如 `2026-01-01T00:30:05Z` 在东八区显示 `2026-01-01 08:30:05`、在西五区显示 `2025-12-31 19:30:05`）；同一时刻的不同偏移原文（Z、`+08:00`、`-05:00`）在同一浏览器时区显示相同的本地日期时间，而鼠标悬浮各自仍是接口返回的完整原文，不把悬浮内容换算成本地时间、也不把两种写法统一；无法识别的非空字符串在格内按原文显示（不补当前时间、不出现 Invalid Date、不附悬浮说明，尖括号等内容只作为文字且不执行），创建时间缺失、为 null 或空字符串时该格空白且无悬浮说明，这些记录仍留在原位置、同行其他配置与前后房间照常显示，不跳过整条房间也不显示加载失败；创建成功后新房间的创建时间遵守同一约定、悬浮原文来自本次创建结果；换算只影响页面显示，查看、刷新与创建后的列表更新都不改写接口返回和本地 rooms.json 中的原始 createdAt。

需要本机安装 Chrome/Chromium，默认使用 `/usr/bin/google-chrome`，可用 `CHROME_PATH=/path/to/chrome npm test` 覆盖。

```sh
curl http://127.0.0.1:8080/health
curl http://127.0.0.1:8080/api/rooms
curl -X POST http://127.0.0.1:8080/api/rooms \
  -H 'Content-Type: application/json' \
  -d '{"name":"晚间五子棋","game":"gomoku","capacity":2,"turnSeconds":0}'
```
